# 미르 (PLAYLABS)

임베디드 입문자를 위한 배선 가이드와 2D 가상 실습 프로그램입니다. Windows EXE와 PC·모바일 브라우저용 HTML 버전을 제공합니다.

2026 충남 직업계고 Microsoft AI 에이전톤 · 아산스마트팩토리마이스터고 PLAYLABS 팀

| 단계 | 누가 | 내용 |
|---|---|---|
| 1. 배선 자동 추천 | **AI** (Copilot Studio 에이전트) | 목표·보드·센서를 말하면 배선을 제안하고 2D 화면에 표시 |
| 2. 2D 가상환경 테스트 | **사람** | 가상 전원과 GPIO를 조작하고 배선을 직접 편집·확인 |
| 3. 오류 진단과 수정 | **AI·사람** | 측정값과 요청을 바탕으로 수정안을 확인하고 적용한 뒤 다시 실습 |

## 실행

- **Windows 앱:** [V106 EXE 다운로드](V106/EXE/mir-V106.exe) 후 실행합니다.
- **웹에서 사용:** [미르 실행하기](https://mir-production-11d1117d.up.railway.app)
- **V106 파일:** [V106 사용 안내](V106/README.md) · [HTML 소스](V106/미르%20HTML)
- **직접 열기:** `V106/미르 HTML` 폴더 전체를 내려받아 `미르 HTML.html`을 브라우저로 엽니다.

로컬 웹 실행은 Node.js 20 이상을 설치하고 **`V106/미르 HTML` 폴더에서** 실행합니다.

```sh
npm ci
npm start
```

브라우저에서 `http://127.0.0.1:8791`에 접속합니다. [실행 안내](V106/미르%20HTML/실행%20안내.md)를 참고하세요.

Windows EXE 빌드는 [V106 Electron 개발 소스](V106/개발소스/Electron)를 참고하세요. HTML 폴더의 명령과 구분합니다.

## 처음 사용하는 경우

1. 빈 제작대에서 **LED 튜토리얼 바로 시작**을 누르세요.
2. 부품함에서 ESP32·220Ω 저항·LED를 직접 꺼내고 안내에 따라 핀을 연결하세요.
3. 가상 전원을 켜고 GPIO26을 HIGH/LOW로 바꾸며 LED를 켜고 끄세요.

튜토리얼은 AI 요청·로그인·API 키 없이 로컬 실습으로 진행합니다. [튜토리얼 안내](V106/미르%20HTML/docs/V106_TUTORIAL.md)를 참고하세요.

## 서버 연결

호스팅된 V106 웹은 승인된 공유 서버의 기존 공개 연결을 사용합니다. 일반 사용자는 API 키나 로그인 정보를 입력하지 않습니다. 실제 AI·DB 기능은 공유 서버가 실행되고 공개 연결이 허용되어 있어야 합니다. 제작대와 튜토리얼은 서버 연결과 별도로 사용할 수 있습니다.

실제 API 키와 Copilot 비밀 키는 서버에서 관리하며 HTML·GitHub 소스에 넣지 않습니다. 로컬 파일 실행의 원격 연결은 서버 CORS 정책에 따릅니다.

- [키 없는 연결 안내](V106/미르%20HTML/docs/V106_KEYLESS_CONNECTION.md)
- [Railway 배포·환경 변수·복구 안내](V106/미르%20HTML/docs/RAILWAY_DEPLOYMENT.md)

## 사용법

- **배선 추천:** 오른쪽 채팅에 만들고 싶은 회로를 설명합니다.
- **배선 편집:** 핀 클릭 → 다른 핀 클릭으로 선을 연결합니다. 선·부품 선택 후 Delete로 삭제하고 Ctrl+Z/Ctrl+Y로 되돌리거나 다시 실행합니다.
- **부품함:** 왼쪽 아래 부품함에서 부품을 검색해 클릭하거나 제작대로 끌어 놓습니다.
- **가상 전원:** 전원을 켜고 연결된 보드 GPIO를 HIGH/LOW로 바꿉니다. 화면의 반응은 가상 계산이며 실제 하드웨어 검증을 대신하지 않습니다.
- **진단 요청:** 이상한 점을 입력하고 진단 요청을 보냅니다. 기존 배선의 수정안은 미리보기를 확인하고 적용합니다.
- **프로젝트 보관:** 파일 메뉴에서 저장하거나 외부 프로젝트를 가져옵니다.
- **화면과 테마:** 메뉴의 설정에서 배선 형태·메인 색상·라이트/다크 모드를 바꿉니다.

## 부품 추가

기본 부품에는 ESP32, Raspberry Pi, 온습도 센서, OLED, LED, 저항, 버튼, 릴레이, 밸브 등이 있습니다.

부품함의 양식 저장과 파일 추가 기능으로 JSON·그림을 가져올 수 있습니다. [부품 안내](V106/미르%20HTML/docs/부품%20안내.html)를 참고하세요. 실제 부품을 연결하기 전에는 제조사 사양과 핀 배치를 별도로 확인하세요.

## 팀 협업 방법 (Copilot)


코드를 잘 몰라도 괜찮아요. **할 일을 적고 → Copilot과 만들고 → 직접 확인하는 순서**로 시작해 보세요.
아래 순서로 팀과 협업할 수 있어요. 이슈 양식과 리뷰용 에이전트는 팀 관리자의 설정에 따라 사용할 수 있어요.

### 1. 할 일을 하나 적어요

GitHub의 **Issues → New issue**에서 양식을 고르세요.

- **기능 요청**: 새로 만들고 싶은 것. 예: “완료한 할 일만 보고 싶어요.”
- **버그 신고**: 잘못 동작하는 것. 예: “저장을 한 번 눌렀는데 두 개가 생겨요.”

한 번에 작은 일 하나만 적고, **어떻게 되면 완료인지** 써 주세요.
팀에서 담당자 한 명을 정해 **Assignees(담당자)**에 지정하세요.
이슈가 만들어지면 붙는 번호(예: `#3`)를 기억하세요.

### 2. Copilot에게 만들어 달라고 해요

담당자는 Copilot 앱에서 저장소를 열고, 그 이슈를 위한 **별도 작업 공간**을 준비하세요.
**브랜치**는 팀의 원본과 섞이지 않게 작업을 나누는 방법이에요. 원본인 `main`에서 바로 작업하지 마세요.
분리 방법을 모르겠다면 변경하기 전에 Copilot에게 물어보세요.

아래 문장의 `#3`을 내 이슈 번호로 바꿔 요청하세요.

> 이슈 #3을 확인해줘. 현재 브랜치와 작업 공간이 다른 작업과 분리되어 있는지 확인하고, 작업 범위와 검증 방법을 쉽게 설명한 뒤 구현해줘.

설명을 읽고 원하는 방향인지 확인하세요. 요청과 다른 내용이 있으면 바로 알려 주세요.

### 3. 검토를 요청해요

작업이 끝나면 Copilot에게 **“이 변경으로 PR을 만들어줘”**라고 요청하세요.
**PR**은 “제가 만든 내용을 팀의 원본에 합쳐도 될까요?”라는 검토 요청이에요.

**PR을 만들기만 하면 리뷰가 자동으로 시작되지는 않아요.**
PR 생성 후 안내에 따라 앱에서 리뷰용 에이전트인 **`student-reviewer`**를 직접 선택하고 요청하세요.

> PR #5를 이슈 #3의 완료 조건에 맞춰 검토해줘.

`#5`는 내 PR 번호, `#3`은 연결 이슈 번호로 바꾸세요. 이슈가 없다면 PR 번호만 적어도 돼요.
이 문장은 요청 예시이며, 실제 에이전트 선택 방법은 앱에서 확인하세요. 검토 결과는 앱에 표시되며 GitHub에 자동으로 게시되지는 않아요.
검토에서 문제가 나오면 개발을 맡은 에이전트에게 수정을 요청하고, 필요한 검사를 다시 한 뒤 리뷰를 다시 요청하세요.
리뷰어가 보이지 않거나 이슈·코드를 읽지 못하면 팀 관리자에게 알려 주세요.

### 4. 내가 직접 써 보고 합쳐요

PR에 적힌 **확인 순서와 기대 결과**를 따라 직접 사용해 보세요. 방법이 없으면 Copilot에게 설명을 요청하세요.
원하는 대로 동작하는지 확인한 뒤 **학생 확인란은 본인이** 체크하세요.

**Copilot이 “검사 통과”라고 해도 직접 확인한 것은 아니에요.**
문제가 없고, GitHub에서 요구하는 검사와 팀원의 승인이 끝나면 권한 있는 사람이 **머지(팀의 원본에 합치기)**해요.
버튼이 막혀 있으면 우회하지 말고 관리자에게 물어보세요.

### 이것만은 기억해요

- 비밀번호·API 키(서비스 접속용 비밀값)·개인정보는 채팅, 코드, 이슈, 화면 캡처에 넣지 않아요.
- 다른 사람의 작업을 지우지 않아요. 로그인·권한·결제·데이터 삭제 같은 중요한 변경은 팀과 먼저 상의해요.
- 모르는 내용은 “초보자도 이해할 수 있게 설명해줘”라고 요청해도 괜찮아요.

- 사람 승인·필수 검사·브랜치 보호·Copilot 자동 리뷰는 별도로 설정하세요. **리뷰어 파일만으로 자동 리뷰·머지 차단·자동 머지가 켜지지 않아요.** 리뷰어 판정과 학생 체크박스도 공식 승인이나 머지 허가를 대신하지 않아요.
- 라벨 생성은 코드 검사가 아니에요. 앱 코드가 생기면 실제 실행·검사 방법을 안내하고 필요한 자동 검사를 준비하세요.

템플릿은 파일만 복사해요. 원본의 권한·보호 규칙은 복사되지 않고, 이후 원본 파일 변경도 자동 반영되지 않아요.
