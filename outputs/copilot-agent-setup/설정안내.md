# 에이전트 파일 적용 방법 — 이 문서만 기준으로 사용

## 앞으로의 수정 원칙
기존 파일명과 경로를 유지하고 내용만 갱신한다. 업데이트용 전체 묶음 ZIP이나 별도 안내문 사본을 만들지 않는다.
한 에이전트에 업로드할 파일은 기술 ZIP 1개와 지식 MD 1개다. 기술 ZIP은 압축을 풀지 않는다.
안내에는 아래의 짧은 역할 문구만 넣고 상세 작업 규칙은 기술에 둔다.

| 에이전트 | 기술: 압축 풀지 않고 업로드 | 지식: MD 그대로 업로드 |
|---|---|---|
| 중앙 설계 | circuit-coordinator-skill.zip | circuit-coordinator-knowledge.md |
| 부품 검색·조사 | component-research-skill.zip | component-research-knowledge.md |
| 회로 설계 | circuit-design-skill.zip | circuit-design-knowledge.md |
| 검증 결과 해석 | validation-interpretation-skill.zip | validation-interpretation-knowledge.md |
| 이미지 제작 | component-image-skill.zip | component-image-knowledge.md |

위 파일은 모두 이 문서와 같은 outputs/copilot-agent-setup 폴더에 있다.
기술 ZIP과 지식 MD는 서로 역할이 다른 파일이며, 둘을 같은 항목에 중복 등록하는 것이 아니다.

## 안내에 넣을 고정 역할 문구

### 중앙 설계
사용자 요청에 따라 부품 검색·DB 등록·이미지 제작·회로 저장과 검증을 조정합니다. 상세 처리 순서는 연결된 circuit-coordinator 기술을 따릅니다. 필요한 부품이 없으면 생성·저장 단계를 진행하고 실제 부품·이미지·회로 ID를 반환합니다.

### 부품 검색·조사
부품을 검색·조사하고 확인한 정보와 미확인 정보를 구분해 미검증 설계 부품으로 DB에 저장합니다. 연결된 component-research 기술을 따르고, 이미지·회로에 쓸 component_id를 반환합니다.

### 회로 설계
중앙에서 전달한 부품 정의와 요구사항으로 구조화된 회로 초안을 작성합니다. 연결된 circuit-design 기술을 따르며 확인되지 않은 핀과 정격은 추측하지 않습니다.

### 검증 결과 해석
미르 DB의 정적 검사 결과를 해석하고, 사용자가 가져온 KiCad 파일에는 ERC와 요청한 ngspice 검사를 실행해 결과를 설명합니다. 연결된 validation-interpretation 기술을 따르고 원래 판정과 검사 범위를 유지합니다.

### 이미지 제작
DB의 component_id를 받아 미르 기본 양식에 맞는 SVG를 직접 제작·저장·적용합니다. 연결된 component-image 기술을 따르고 실제 적용 결과를 반환합니다. 기본 제작에는 별도 OpenAI API 키가 필요 없습니다.

## 기존 에이전트 업데이트
1. 해당 에이전트의 안내를 위 역할 문구로 맞춘다. SKILL.md 본문 전체를 안내에 다시 붙이지 않는다.
2. 기존 기술 항목을 같은 이름의 skill.zip 파일 내용으로 갱신한다. ZIP 안의 SKILL.md를 따로 업로드하지 않는다.
3. 기존 지식 항목을 같은 이름의 knowledge.md 파일 내용으로 갱신한다.
4. Studio 화면에서 기존 항목의 파일 교체를 지원하지 않으면 이전 항목을 제거한 뒤 같은 기준 파일을 한 번만 등록한다. 이전 것과 새 것을 함께 남기지 않는다.
5. 해당 역할의 기술 1개·지식 1개만 남았는지 확인한다. 다른 목적의 지식·도구는 임의로 지우지 않는다.
6. 필요한 도구·전문 에이전트 연결을 유지하고 변경 사항을 게시한다. 웹사이트는 Ctrl+F5로 새로고침한다.

같은 파일명을 다시 업로드한다고 Studio가 자동으로 기존 항목을 덮어쓴다고 가정하지 않는다.
로컬 파일 수정이 이미 업로드된 Studio 설정에 자동 동기화되는 것도 아니다. Studio에는 기존 항목의 내용 갱신이 필요하다.

## 편집 원본 — 사용자 업로드 대상 아님
각 에이전트 하위 폴더의 SKILL.md가 상세 지침의 유일한 편집 원본이다.
예: component-image/SKILL.md → component-image-skill.zip.
개발 작업에서는 SKILL.md와 기존 knowledge.md를 수정하고 다음 명령으로 같은 ZIP을 갱신한다.

```powershell
.\.venv\Scripts\python.exe scripts/sync_agent_packages.py
```
원본과 ZIP이 같은지는 다음 명령으로 확인한다.

```powershell
.\.venv\Scripts\python.exe scripts/sync_agent_packages.py --check
```
사용자가 위 명령을 매번 실행할 필요는 없다. 작업자가 파일 수정 후 ZIP까지 반영한다.

## 현재 도구 구성
기존 CircuitAgent 연결을 사용한다. 현재 총 24개 도구이며 CreateComponent는 중앙·부품 검색 에이전트가 사용한다.
이미지 에이전트는 기존 이미지 도구를 사용한다. 중앙·검증 결과 해석 에이전트에는 GetCircuitVerificationConfig, ImportKiCadProject, GetKiCadProject, VerifyKiCadProject, GetJobStatus를 활성화한다. 전문 에이전트 연결은 유지한다.
검색 → DB 저장 → 이미지 연결 흐름과 연결 설명은 프로젝트 COMPONENT_PIPELINE_SETUP.md에 있다.
디자인 세부 규칙은 이미지 기술과 지식, 기술 참고는 IMAGE_AGENT_SETUP.md에 있다.
API 키 파일, .env, DB, 로그는 지식으로 올리지 않는다.
