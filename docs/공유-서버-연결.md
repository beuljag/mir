# 공유 배선 서버 연결

## 미르 사용자

- 웹에서 사용하려면 서버 관리자가 알려준 HTTPS 주소의 `/mir/`를 엽니다.
- 새 `mir-shared.exe`를 받았다면 실행합니다. 기본 공유 서버로 자동 연결합니다. 다른 서버를 쓰려면 **연결 설정 → 서버 API → 공유 서버**에서 HTTPS 기본 주소를 입력합니다.
- 공개 공유 서버에서 배선 API 키는 빈칸으로 둡니다. 비공개 서버나 KiCad·ngspice 파일 검증에 연결할 때는 해당 서버의 배선 API 키를 입력합니다.
- 공개 공유 서버 사용자는 채팅과 부품 조회, 회로 불러오기·저장·기본 검증을 이용할 수 있습니다.

## 서버 관리자

1. 서버 PC의 `.env`에 `CIRCUIT_API_KEY`, `COPILOT_DIRECT_LINE_SECRET`, `MIR_PUBLIC_ACCESS=1`을 설정합니다. Copilot Studio MCP 도구의 공유 연결도 같은 배선 키 또는 같은 DB 소유자에 매핑된 키를 사용합니다.
2. API를 재시작하고 `서버켜기.bat`로 고정 Dev Tunnel이 실행 중인지 확인합니다.
3. 사용자에게 HTTPS 주소의 `/mir/` 또는 새 실행 파일을 전달합니다.

공개 설정을 켜면 주소에 접근할 수 있는 사람이 서버의 Copilot 사용량과 해당 키의 회로 DB를 공유합니다. 회로는 ID로 불러오므로 공유할 회로의 ID만 전달하세요. 전용 API가 허용한 편집 작업만 배선 키 없이 사용할 수 있습니다. 공개 접근을 닫으려면 `MIR_PUBLIC_ACCESS=0`으로 바꾸고 API를 재시작합니다.

## Windows 실행 파일 빌드

`npm ci`로 의존성을 설치한 뒤 `npm run dist`를 실행하면 `release-shared-auto/mir-shared.exe`가 생성됩니다. 기본 주소는 `renderer/server-defaults.json`에서 읽습니다. 주소를 바꾸려면 `MIR_DISTRIBUTION_SERVER_URL` 환경 변수 또는 `config/distribution-connection.local.json`의 `url` 속성을 사용합니다. 빌드에는 HTTPS 주소만 포함됩니다.

## 연결 확인

- 연결이 실패하면 서버와 터널이 실행 중인지, 주소를 정확히 입력했는지 확인합니다.
- PC마다 오래된 HTML이나 EXE를 사용 중이라면 최신 편집기를 열거나 새 실행 파일로 교체합니다.
- Direct Line 인증 오류는 서버의 Direct Line 비밀 키를 확인합니다.

## CircuitAgent 연결 필요 오류와 부품 생성 시간 초과

2026-10-29 실제 미등록 보드 요청에서 Copilot은 `Connection Required / CircuitAgent / Set up your connection, then select Retry` 카드를 반환했습니다. 이는 Direct Line 채팅 연결 성공과 별개인 도구 연결 요구입니다. 부품 생성 성공을 의미하지 않습니다.

- Copilot Studio에서 중앙 에이전트와 해당 도구를 호출하는 연결 에이전트의 **도구 → CircuitAgent**를 엽니다.
- 저장된 MCP 연결이 유효한지 확인합니다. 도구의 인증/사용할 자격 증명에 **Maker-provided credentials(제작자 제공 자격 증명)**를 선택할 수 있다면 현재 서버 API 키로 만든 제작자 연결을 선택하고 저장·게시합니다.
- 메뉴가 없거나 비활성화되어 있으면 인증 채널이나 환경 정책의 제한을 확인해야 합니다. 에이전트의 ‘인증 없음’을 임의로 바꾸면 기존 Direct Line 연결 방식에도 영향이 있으므로 먼저 도구 상세 설정을 확인합니다.
- 공식 문서: https://learn.microsoft.com/en-us/microsoft-copilot-studio/add-tools-custom-agent

클라이언트는 실패한 대화를 정리하고 다음 사용자 요청을 새 대화로 보냅니다. 기존 요청을 자동 재전송하지 않습니다. 서버 기본값은 대기 제한 해제이며, `.env`의 `COPILOT_REPLY_TIMEOUT_SECONDS`에 30~900초를 지정할 수 있습니다. 카드 응답도 읽고, 연결 필요 카드에는 명시적 오류를 표시합니다. 대기 시간을 늘리는 것만으로 도구 연결 요구가 해결되지는 않습니다.

## 부품 등록 후 배선 그림이 없을 때

부품 정의·이미지와 회로 인스턴스·nets·layout은 별도 데이터입니다. 부품 등록만 완료된 응답으로는 선을 그리지 않습니다.
설계 요청은 회로 저장까지 진행하고 실제 circuit_reference JSON을 반환하도록 전달합니다. pins=[]인 초안은 공식 핀맵을 추가 조사하고 새 정의로 보완합니다. 회로가 저장되면 빈 캔버스에서는 자동으로 불러오며, 편집 중인 화면에는 불러오기 버튼을 제공합니다. 불러오기 버튼은 회로를 실제 조회합니다.
새 부품으로 wiring JSON을 반환한 경우에도 DB 부품·이미지를 먼저 새로 읽은 후 배선을 그립니다. 회로 ID나 wiring 데이터가 없다면 그림을 만들지 못한 이유를 표시합니다.
설계 요청은 진행 중 메시지를 최종 답변으로 처리하지 않도록 명시적 완료 표식을 요청합니다. 표식은 사용자 화면에 표시하지 않습니다. 확인된 핀이 부족하면 임의 배선 대신 최종 확인 질문으로 종료할 수 있습니다.

## DIRECT_LINE_NETWORK_ERROR

이 오류는 서버와 Microsoft Direct Line 사이의 통신 오류이며 인증 실패 코드와 다릅니다. GET 조회는 최대 세 번 재시도하고, 조회 장애가 잠시 지속돼도 대화 상태를 유지해 복구를 기다립니다. 장애가 계속되거나 전체 응답 대기 시간이 지나면 종료합니다. 부품·회로 생성 등 POST 전송은 자동 재전송하지 않습니다. 오류 이후에도 원격 작업은 진행 중일 수 있으므로 동일 설계를 다시 요청하기 전에 DB 상태를 확인합니다.

## 필수 모델·사양 확인 질문

확인 질문은 clarification JSON의 questions에 필요한 부품명과 모델·사양만 담습니다. 이때 화면에는 질문만 표시하고 내부 오류 설명이나 회로 데이터 부재 안내를 추가하지 않습니다. 실제 연결·통신 오류와 완료된 회로의 검증 상태는 이 질문 처리와 별개입니다.

확인 질문은 조사보다 우선하지 않습니다. DB·공식 자료에서 찾을 수 있는 핀맵과 정격은 에이전트가 먼저 조사하고, 실제 제품을 특정할 수 없을 때만 모델명·제조사 등 최소 식별 정보를 묻습니다. 공개 자료가 없는 사용자 제작 보드는 자료 링크나 핀맵 확인이 필요할 수 있습니다.

## 검색 기능과 문서 분석의 차이

범용 서버 웹 검색에는 BRAVE_SEARCH_API_KEY 설정이 필요합니다. 키가 없으면 Copilot의 웹 검색이 찾은 source_urls를 전달하거나 제한된 공식 자료 경로/참고 자료 카탈로그를 사용합니다. 참고 자료 카탈로그 조회는 범용 웹 검색이 아닙니다.
문서 분석 결과의 agent_extraction_tasks는 에이전트가 본문에서 추출할 항목으로, 사용자 입력 폼이 아닙니다. document_sections와 evidence를 확인하며, 출처 제목의 모델 식별자와 정확한 모듈 변형도 구분합니다. 다른 회사의 같은 칩 모듈 자료에서 읽은 정격과 물리 핀 순서를 대상 모듈에 그대로 복사하지 않습니다.
현재 미르 채팅은 텍스트와 배선 정보만 전송합니다. Codex 대화에 첨부한 사진이 미르의 Copilot 에이전트에 자동으로 전달되지는 않습니다. 사용자 메시지나 출처에서 확인된 핀 표기는 미확인 정격과 구분해 재사용합니다.
