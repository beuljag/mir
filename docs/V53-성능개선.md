# V53 부품 드래그 성능 개선

## 원인

매 mousemove마다 전체 SVG를 재생성하고 모든 전선의 겹침 구간을 SVG 경로 샘플링으로 다시 계산했습니다. 기본 곡선 모드에서도 사용하지 않는 정렬 경로를 반복 계산했습니다. 전체 DOM 변경을 감시하는 창 색상 처리도 매번 같은 색상 IPC를 전송했습니다.

## 수정

- 드래그 화면 갱신을 requestAnimationFrame으로 묶어 표시 주기당 최대 한 번 실행합니다.
- 드래그 도중에는 연결 끝점을 따라가는 경량 경로를 표시합니다. 직선 모드에서도 드래그 중 임시 곡선이 보이며 놓으면 직선 경로로 정리됩니다.
- 정식 장애물 회피 경로와 겹침 밝기 계산은 놓을 때 실행합니다. 연결 관계는 변경하지 않습니다.
- 마지막 프레임 대기를 취소하고 최종 위치를 적용하여 놓는 순간 위치가 누락되지 않도록 처리합니다.
- 창 버튼 색상이 같으면 IPC 전송을 생략합니다.

## 측정

동일한 ESP32 밸브 예제에서 60회 이동 입력을 보내 V52와 V53 패키징 앱을 비교했습니다. 측정은 이 PC와 예제 조건의 결과이며 모든 회로의 성능을 보장하지 않습니다.

| 항목 | V52 | V53 |
| --- | ---: | ---: |
| render 호출 | 61 | 24 |
| render 총시간 | 3312ms | 123ms |
| render 평균 | 54.3ms | 5.1ms |
| 겹침 계산 호출 | 61 | 1 |
| 창 색상 IPC | 71 | 1 |

V53 render 최대 69ms는 놓은 후 최종 경로 및 겹침 계산을 포함합니다. 마우스 이동 중의 반복 계산은 제거했습니다.

## 검증

곡선·직선 모두 드래그/놓기, 배선 데이터 보존, 최종 경로 생성, 되돌리기를 패키징 앱에서 확인했습니다. 화면 오류 0개. 자동 검사 59개 통과.
