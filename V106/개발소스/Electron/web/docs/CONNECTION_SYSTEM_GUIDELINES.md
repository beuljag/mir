# MIR 서버 연결 시스템 근본 개선 지침

2026-11-16 사용자가 추가한 개발 지침입니다. 이 문서는 향후 구현과 검증의 기준이며, 지침 저장만으로 기능 구현이나 운영 반영이 완료된 것은 아닙니다. 앞서 정한 Railway 자동 연결 보안 정책과 함께 적용합니다.

## 목표

MIR HTML에서 반복적으로 발생하는 서버 연결 실패, 인증 초기화, 자동 연결 실패, Railway 호환성 문제를 근본적으로 해결한다.

단순 오류 수정이 아닌 서버 연결 시스템의 구조적 개선을 진행한다.

## 1. 기존 시스템 분석

다음 파일과 관련 의존관계를 분석한다.

- serve.cjs
- assets/server-connection.js
- assets/web-api.js
- 미르.js
- 서버/run.py
- 서버/app/main.py
- 서버/app/local_connection.py
- 서버/app/mir_web.py
- MCP 관련 모듈
- Copilot Direct Line 관련 모듈
- Electron 연결 모듈

번들링된 미르.js만 직접 수정하지 않는다. 원본 소스와 빌드 시스템을 확인하여 원본을 수정하고 번들을 다시 생성한다.

## 2. 통합 Connection Manager 구현

기존 연결 기능을 분석하고 공통 서버 연결 모듈을 설계한다.

담당 기능:

- 실행 환경 감지
- 서버 주소 관리
- 연결 상태 관리
- 사용자 인증 및 세션 관리
- API 요청 관리
- 연결 오류 진단
- 자동 재연결
- 연결 해제
- 요청 타임아웃
- 서버 상태 모니터링

HTML, 모바일, EXE에서 공통 연결 로직을 사용하도록 구성한다.

## 3. 서버 연결 환경

다음 환경을 지원한다.

- Windows 로컬 서버
- 친구의 공유 서버
- Railway 클라우드 서버
- PC 웹 브라우저
- 모바일 웹 브라우저
- Electron EXE

Railway에서는 MIR_BACKEND_URL을 기준으로 승인된 백엔드에 연결한다.

서버 주소를 프론트엔드에 고정하지 않는다.

임의의 외부 주소로 요청을 전달할 수 있도록 기존 보안 제한을 해제하지 않는다.

## 4. 인증 시스템 개선

현재 API 키가 빈 문자열로 초기화되어 자동 연결에 실패하는 문제를 해결한다.

사용자 인증과 서버 간 인증을 분리한다.

- 사용자: 로그인 및 세션 기반 인증
- 서버: 환경 변수 기반 비밀 인증 정보

웹 브라우저에는 관리자 API 키나 Copilot Secret을 전달하지 않는다.

세션 쿠키에는 HttpOnly, Secure, 적절한 SameSite 정책을 사용한다.

CSRF, 세션 만료, 로그아웃 및 사용자별 권한 분리를 구현한다.

사용자 인증 없이 관리자 API 키를 대신 사용하도록 구현하지 않는다.

## 5. 자동 연결 및 복구

HTML이 시작되면 승인된 백엔드의 상태를 확인한다.

서버가 연결되지 않는 경우 재시도를 수행한다.

- 초기 재시도: 5초
- 반복 실패 시 점진적으로 간격 증가
- 최대 재시도 간격: 60초
- 서버 복구 시 자동 재연결
- 인증 실패 시 무한 재시도 금지
- 인증 만료 시 재로그인 안내
- 중복 요청 및 중복 세션 생성 방지
- 페이지 종료 시 불필요한 요청 정리

위 재시도 시간은 기본 제안이며 서버 부하와 기존 구현에 맞춰 조정한다.

## 6. 연결 상태 세분화

다음 상태를 독립적으로 관리한다.

- 웹 서버
- 백엔드 서버
- 사용자 인증
- 배선 DB
- MCP 서버
- Copilot AI
- 회로 검증 도구

일부 기능이 실패하더라도 정상 기능까지 불필요하게 차단하지 않는다.

오류 발생 시 어느 단계에서 실패했는지 표시한다.

401, 403, 404, 429, 502, 503, 타임아웃 등을 구분하여 안내한다.

## 7. 보안 정책

- 기존 API Key 인증 유지 및 안전한 통합
- 승인된 백엔드 주소 검증 유지
- SSRF 방어 유지
- 사용자별 데이터 접근 권한 분리
- 요청 횟수 및 사용량 제한
- 공개 API의 권한 검사
- 비밀 정보의 로그 출력 금지
- HTML 및 JavaScript에 비밀 키 삽입 금지
- GitHub 커밋에서 비밀 파일 제외
- 인증 우회 방식의 문제 해결 금지

## 8. Railway 호환성

기존 mir 및 calm-vibrancy 서비스를 유지한다.

HOST, PORT, MIR_DEPLOYMENT, MIR_WEB_ORIGIN, MIR_BACKEND_URL 등 기존 환경 변수를 지원한다.

기존 Volume 및 데이터베이스를 보존한다.

Windows 전용 실행 방식과 Linux 클라우드 실행 방식을 분리한다.

업데이트 과정에서 기존 Railway 호환 코드를 삭제하거나 덮어쓰지 않는다.

- 서버 종료 후 재실행 시 재연결
- 새로고침 시 유효한 로그인 세션 유지
