# V106: 현재 웹에서 API 키 입력 없이 에이전트 사용

## 변경 범위

로그인, 게스트 세션, 호출 횟수 제한, 사용량 제한을 추가하지 않았습니다. 서버의 인증 기능을 제거하지 않았고 실제 키를 웹 실행기에 복사하거나 브라우저에 전달하지 않습니다.

현재 공유 서버는 관리자가 `/mir/api` 공개 연결을 이미 활성화한 상태였습니다. 기존 웹 중계가 키가 비어 있으면 그 연결까지 거부하는 것이 원인이었습니다. Railway 웹은 이제 MIR_BACKEND_URL로 승인된 서버의 기존 공개 연결을 사용하며 사용자 키 헤더를 전달하지 않습니다. 공개 연결을 끈 서버의 403 응답은 그대로 존중합니다.

- `serve.cjs`: 클라우드 키 필수 검사를 기존 공개 연결 경로로 변경. 출처·백엔드·API 경로·HTTPS·리디렉션 제한은 유지.
- `assets/web-api.js`: 호스팅 메타데이터로 공개 연결을 인식. 자동 연결과 재확인에 사용자 키를 사용하지 않음.
- `assets/app.js`, `미르 HTML.html`: 호스팅 공개 연결에서는 키 입력칸과 불필요한 키 안내를 숨김. 서버 주소는 운영 설정 그대로 사용.
- `미르.js`: 위 원본에서 재빌드. 번들만 직접 수정하지 않음.
- `mir-version.json`: V106 표시.
- `AGENTS.md` 17절: 로그인·사용량 제한을 추가하지 말라는 최신 범위 정정 기록.

## 검증

- Node 자동 검사 31건 통과: 키 없는 요청, 사용자 키 헤더 무시, 잘못된 출처/백엔드/경로 차단, 공개 연결 비활성 서버의 거절 유지, HOST·PORT·시작 회귀.
- Chrome PC 1440px/모바일 390px: 자동 DB 연결, 모의 AI 응답, 키 입력칸 숨김, 새로고침 후 연결, LED 예제와 되돌리기 기능 확인. 브라우저 요청에 API 키 헤더 없음, 페이지 실행 오류 없음.
- 실제 공유 서버: 수정한 웹 중계를 통해 키 없이 DB 부품 17개 조회, AI 구성 확인, Direct Line 대화 생성, 짧은 연결 테스트에 대한 실제 AI 답변 수신, 테스트 대화 삭제 성공. 답변 본문이나 비밀 값은 검사 로그에 출력하지 않음.
- 추가로 새 로그인·제한 코드가 들어가지 않았는지 변경 범위를 확인.

## 반영과 한계

새 환경 변수·키 입력·로그인 설정이 필요하지 않습니다. 기존 MIR_BACKEND_URL과 공유 서버의 공개 연결 설정을 그대로 유지합니다. 웹사이트에 적용하려면 검사를 마친 변경을 사용자 승인 후 main에 반영해야 합니다. 이 문서 작성 시점에는 운영 배포하지 않았습니다.

로컬 파일/EXE의 기존 인증 방식은 변경하지 않았습니다. 이번 변경은 현재 호스팅 웹 연결에 한정하며 실제 EXE 재빌드·Linux 신규 CI·수정본 운영 배포는 아직 미검증입니다. 공개 연결의 권한 범위는 기존 공유 서버 정책을 따르며 새 사용자별 분리를 구현한 변경은 아닙니다.
